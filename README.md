# 🤖 HR-Tech AI Agent: Интеллектуальный помощник для ИТ-рекрутмента

## 📌 Описание проекта
Данный проект представляет собой разработку специализированного **AI-Агента (OSINT-ассистента)** для отдела кадров в Digital-компании. 

**Цель системы** — автоматизированная помощь HR-специалистам в составлении профилей должностей, матриц компетенций и онбординг-материалов путем предоставления достоверных и точных справок по сложной ИТ-терминологии.

---

## 🎯 Проблема и предлагаемое решение

**❌ Проблема:** В сфере ИТ-рекрутмента кадровым специалистам необходимо ежедневно оперировать сложными техническими понятиями (фреймворки, архитектурные паттерны, методологии). Использование базовых больших языковых моделей (LLM) для этих целей несет критические риски — модели склонны к **галлюцинациям** (могут выдумать несуществующие концепции или исказить суть технологии).

**✅ Решение:** Для устранения проблемы реализована концепция **Agentic Workflow** (Агентный подход). Агенту строго запрещено генерировать фактологическую информацию из собственных "весов". Вместо этого он использует инструмент доступа к энциклопедической базе для извлечения детерминированных и проверяемых данных.

---

## 🛠 Технологический стек
* **Оркестрация:** LangChain, кастомный Orchestrator.
* **Генеративная модель (LLM):** `Qwen/Qwen2.5-1.5B-Instruct` (загружена в формате `float16` для предотвращения Out-Of-Memory ошибок).
* **Работа с NLP:** HuggingFace Transformers.
* **Внешние инструменты (Tools):** `WikipediaQueryRun` (Wikipedia API).

---

## 🧠 Особенности архитектуры (Custom Orchestrator)

В ходе разработки был выявлен архитектурный конфликт между внутренним механизмом очередей стандартного `AgentExecutor` из библиотеки LangChain и форматом вывода локальной модели, что приводило к зависанию процесса (`queue.Empty`). 

Для обеспечения 100% стабильности системы стандартный движок-"черный" ящик был заменен на **кастомный прозрачный оркестратор**. Процесс работы агента разделен на три строго контролируемых этапа:

1. **Извлечение (Extract):** LLM анализирует запрос кадровика естественным языком и вычленяет из него целевой ИТ-термин.
2. **Поиск (Search):** Скрипт обращается к Wikipedia API и получает "сырые" проверенные факты.
3. **Генерация (Generate):** LLM анализирует полученные факты и формирует понятную HR-справку.

## 📊 Система мониторинга и телеметрии

Для контроля производительности и стабильности реализован класс мониторинга `AgentMonitor`, который собирает телеметрические данные в реальном времени.

**Собираемые метрики:**
1. ⏱ **Execution Time** — общее время ответа системы.
2. 🔄 **LLM Calls** — количество циклов рассуждения нейросети (нагрузка на GPU).
3. 📚 **Tool Calls** — количество обращений к внешним базам знаний.

*Тестирование показало, что агент успешно извлекает факты и формирует корректные ответы без признаков неконтролируемой генерации, сохраняя при этом стабильную работу памяти (RAM/VRAM).*
